# Scene delta — 工具市场 / 插件平台型 (Marketplace & Platform)

市场与平台类仓库的核心矛盾是：**终端安装者只想一行命令装完走人，而生态作者需要理解复杂的规范**。必须通过严格的视觉层级与入口分流解决。

---

## 1. 骨架规范（<= 200 行标准动线）

```markdown
# 项目名称
一行人话：解决了什么平台的什么核心痛点。

[状态徽章 <= 3 枚: Stars / CI / License]

[首屏单行指标: 核心数据 · 索引频率 · 分发机制 · 速率保障]

[产品截图: 真实 Web GUI 插件市场界面 (非概念海报/非 social-preview)]
<!-- 缺截图时的合法降级: 第一折直接进入安装命令，严禁使用 OG 封面卡充当产品图 -->

## 安装
官方 CLI 单行命令 + 卸载命令 + 备用脚本说明
> [!WARNING]
> 针对远程安装脚本的信任边界提示。

## 在设置页里做什么
5 步以内的直观图文操作流 (安装/传参/更新/已安装)。

## 和自己搜 GitHub 差在哪
单张高密度能力矩阵表（分发机制、版本对比、安全确认、类型嗅探），严禁拆分两张同义表。

## 插件作者如何被收录
三行说明收录机制，核心开发指引直连 STANDARD.md。

<details>
<summary>工作原理与核心架构</summary>
真实数据流 Mermaid 流程图 (反映 CDN 分发与 GitHub 搜索 API 兜底逻辑)。
</details>

<details>
<summary>本地存储结构与 HTTP API 摘要</summary>
完整的 API 表与 ~/.dsh/ 目录树。
</details>

## 已知限制与免责声明
第三方代码执行边界说明、社区收录非背书声明，详细限制链至 docs/。
```

## 2. 真实活体夹具：DSH-Plugins-Marketplace 改造前后对照

| 维度 | 原版问题 (AI 模板风) | 改造后规范 |
|---|---|---|
| **标题装饰** | `[Emoji] 核心优势`, `[Emoji] 一键安装` 等套话 | 彻底移除 Emoji，直接用任务名：`安装`, `在设置页里做什么`, `和自己搜 GitHub 差在哪` |
| **首屏插图** | 误将 `assets/social-preview.png` (OG 卡) 当成产品图 | 缺截图时合法降级：首屏直接承接安装命令，图位显式留白待补 |
| **首屏徽章** | 8 个 Shields.io 彩色徽章横向通铺 | 精简为 3 个关键状态：GitHub Stars、Registry CI、License |
| **指标呈现** | 4 列 HTML 嵌套表格，移动端易碎 | 单行中圆点分隔：`9500+ DSH 插件 · 20000+ 通用 Skills · 2 小时增量同步 · 0 API 限流` |
| **内容重复** | `核心优势` (8行表) 与 `功能特性` (25点列表) 严重同义反复 | 合并为单张「能力对照表」，客观表述静态索引与 API 回退机制 |
| **流程图保真** | 误将 CDN 写为 push 目标且删去 API 兜底 | Mermaid 严格反映：CI 提交 $\to$ CDN 缓存 $\to$ 搜索 API 兜底 |
| **必要声明** | 删去卸载命令、限制与免责声明以凑行数 | 保留卸载命令、已知限制与第三方代码免责声明，总行数控制在 150 行内 |
