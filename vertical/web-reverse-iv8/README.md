# web-reverse-iv8

# 初版，比较草稿，迭代版本正在开发，方法论重新设计，效率更高，适用性更广，支持更多国模。

> Web JS 加密参数逆向实战 Skill —— 从 HAR 参数溯源到本地模拟验证的完整链路方法论。

`web-reverse-iv8` 是一个面向 AI Agent 的逆向工程方法论 Skill，覆盖 web 端 JS 加密参数（如 `sign` / `w` / `token`）的完整分析链路：**参数溯源 → 加密点定位 → 保护类型识别 → 方案选择与执行 → 本地验证**。

它不是某个具体破解脚本，而是一套**可被 Agent 复用的、带阶段门硬阻断的工作流规范**，确保逆向过程可审计、可复现、不跳步。

当前版本：**v9.6**

---

## 适用定位

本 Skill 专为**高对抗强度**场景设计，**通杀一线大厂**的加密方案（如极验、网易易盾等带 JSVMP / WASM / Worker / OB 壳 / eval-Function 壳 / Webpack 多 chunk 打包的强保护链路），通过四阶段工作流 + 阶段门硬阻断 + iv8 补环境，系统化拆解复杂加密。

**中等、简单场景不适用**：对于无保护或弱保护的简单 sign / token，本 Skill 的阶段门、manifest 校验、产物整理流程属于杀鸡用牛刀，反而增加无谓开销。这类场景建议直接读 JS 或用轻量工具快速定位即可。

---

## 核心特性

- **四阶段工作流**：日志基础分析 → 字符串恢复与溯源 → 载体形态判定 → 本地模拟与验证。
- **阶段门硬阻断**：进入阶段 N 前必须运行 `scripts/stage_gate.py`，前置产物缺失或 schema 校验失败 → BLOCK，禁止"先斩后奏"。
- **从内向外、最小执行范围**：先分析依赖图，只执行最小必要代码，避免"让整个应用跑起来"的无限攻击面。
- **方案 1 / 方案 2 双路径**：算法可静态还原 → Python 重写；有浏览器依赖 / JSVMP / Worker → iv8 补环境。
- **标准化交付**：任务完成有"产物整理流程"，任务失败有"失败交付物"模板。

## 环境要求与依赖

### 核心依赖

| 依赖 | 说明 |
|------|------|
| Python 3.8 – 3.14 | 主语言环境 |
| iv8 社区版 | `pip install iv8`，方案 2 补环境核心运行时 |
| httpx | HTTP 发包验证 |

### 可选依赖

| 可选依赖 | 用途 |
|---------|------|
| curl_cffi | TLS 指纹模拟 |
| wasmtime / pywasm | WASM 加密场景 |
| Node.js | Webpack bootstrap 拆解等纯计算备选方案 |

### 输入（用户提供）

| 输入 | 必需性 | 用途 |
|------|--------|------|
| HAR 文件 | **必需** | 参数溯源 + `_initiator.stack` 提取（加密点定位起点） |
| trace 文件 | 可选 | 阶段一环境指纹采集；无 trace 则方案 2 用 iv8 debug 探测 |
| 目标 JS 文件 | 从 HAR 提取 URL 自行下载 | 加密逻辑载体 |

> 无 HAR → Skill 无法启动。
